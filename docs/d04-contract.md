# D04 — Composed navigation, typography and owner-local theme assets

Date: 2026-10-07 (Tokyo). Delivery follows verified D03, PR #19. Scope derives from D04/F016/F019; broader Elementor adaptation, arbitrary executable extensions and physical multi-host certification retain their own packages.

## End-user outcome

An owner authors and publishes an independent responsive theme with hierarchical/grouped navigation, reusable layout/style controls and self-hosted typography/assets. The same composition appears in private preview and deliberately published visitor output. Designers can inspect changes, preserve their draft on conflicts, export/recover the admitted graph and return to a previous revision. Visitors retain readable content, keyboard/touch navigation and usable narrow/RTL layouts without mandatory remote fonts, accounts or scripts.

## Work sequence and authority

1. Finalize bounded declarative navigation, typography, style and asset grammars from existing package authority. Define limits and unsupported inputs before adding persistence. Current flat site navigation writes immediately; composed navigation must share the theme's draft/live version and cannot leak a preview into live settings. Define language override precedence explicitly. Document any package/native/portable format change and retain the actual schema-18 executable for upgrade/fresh rollback.
2. Deliver native hierarchical/grouped navigation and connected authoring controls first. Use semantic lists and disclosures; ordinary site links do not become ARIA application menus. Retain meaningful no-JavaScript behavior, touch/keyboard access, visible focus and deterministic escape/focus behavior where a disclosure enhancement is used. Do not copy an illustrative accessibility example as production certification.
3. Deliver explicit supported typography and bounded reusable styles. Local font/asset admission must validate actual containers with bounded work; extensions/signatures alone are insufficient. Retain immutable identifiers, checksums, provenance/license metadata and safe content types. Do not loosen the image pipeline to arbitrary files. Reject script/event/import/network/file authority in style and font declarations. Any trusted-owner CSS capability must state its actual admitted grammar; controlled declarations do not justify an arbitrary raw CSS claim.
4. Integrate preview, CAS draft save/publication, activation, revision restore, independent package authoring and portable recovery. Draft assets require authenticated preview; public exposure follows admitted published references. Recheck current credentials and dependencies at mutation, and preserve content/member/privacy/form authority. Owner asset files must not escape the data directory or expose unrelated/private material.
5. Verify each connected functional slice, then optimize the whole theme workflow. Use a few readable high-level scenarios across real SQLite/PostgreSQL: draft/live separation, stale/concurrent edit, invalid/deep/oversized graphs, unsafe style/asset refusal, private/public boundary, cache invalidation, recovery and actual previous-runtime upgrade/rollback. Measure real desktop/narrow/RTL geometry, font readiness/layout change, keyboard behavior, focus/contrast/reduced-motion and inspect screenshots. Report assistive-technology limits honestly.
6. Record request/render/query budgets, cache behavior, asset bytes and app memory/disk under stated conditions. Preserve all applicable cumulative gates and final-head exact-source clean-archive verification. Deliver a significant PR and merge only once ready under standing authorization, then verify actual-main publication separately.

## Primary guidance and evidence protocol

Checked 2026-10-07: [W3C APG disclosure navigation](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/examples/disclosure-navigation/) (updated 2026-01-20), [WOFF2 Recommendation](https://www.w3.org/TR/WOFF2/) (2024-08-08), and [font-display](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@font-face/font-display). APG examples require independent browser/assistive-technology verification. Font loading/fallback requires actual measured readiness and layout behavior. Refresh feature-guidance records, decisions, matrix and retained gaps before affected implementation or newly introduced dependencies.

Current WordPress primary references: [Navigation block](https://wordpress.org/documentation/article/navigation-block/) updated 2026-09-27 for 7.1; [Font Library](https://wordpress.org/documentation/article/the-font-library/) updated 2026-07-26; [theme typography settings](https://developer.wordpress.org/themes/global-settings-and-styles/settings/typography/). These describe nested navigation, connected type controls and fonts hosted locally after installation. Documentation inspection is not executed WordPress/plugin parity. Local upload remains independent of outside font catalogs; no automatic vendor download is required.

## Explicit limits

No paid plugin access, external API credentials, arbitrary extension execution, universal accessibility certification or app-license/support adoption is inferred. Theme asset licensing is a separate provenance requirement. Declare initial font/container/style/navigation limits and preserve remaining useful breadth in the backlog rather than silently marking the whole catalog complete.
