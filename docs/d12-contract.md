# D12 — Deliberate offline library and consented response recovery

2026-10-13. Starts from independently verified D11 main/public release `22e29f7d3a310f565a97107bbb5b5f328ec1d39b` ([receipt](evidence/d11-main-release.json)). Catalog F045/F046. This is a defined local system, not universal offline synchronization or paid-plugin runtime parity.

## End-user outcomes

A visitor deliberately saves anonymous public articles and eligible scalar forms to a private-device library, reopens them without a connection, sees original source/version/age and seven-day expiry, and deletes individual items or clears the library. The reading projection contains validated article text, not arbitrary themed HTML, remote assets or interactive embeds. Forms with account/financial/attachment/signature/acknowledgment inputs require an online visit. Ordinary browsing does not save content. Offline drafts are work in progress: sending requires reconnection and deliberate review. Changed publications never silently remap answers or discard an unresolved original submission identifier/payload.

An owner publishes a specific partial-response recovery purpose and safe-field selection for the current form publication. A visitor separately requests owner review/reminder, confirms the recipient address, can withdraw/delete their partial record, and receives at most one purpose-specific reminder. Saving a private draft, leaving the page and marketing subscriptions grant no such permission. Unconfirmed values are not exposed to editors. Publication/policy change, expiry, withdrawal and completed matching submission fence queued delivery. Existing mail uncertainty rules still apply: completed or ambiguous delivery cannot be undone.

## Authority, bounds and lifecycle

Worker scope is `/offline/`, never root. Origin-wide Web Locks serialize activation cleanup and all snapshot admission/removal across worker updates; unsupported coordination refuses with a live-site alternative. Cache only its fixed shell/assets and deliberately requested, bounded anonymous snapshot representations. Fetch snapshots without credentials; allowlist exact local routes, response markers/types/origins and no redirects. Credential omission suppresses cookie sending and response-cookie processing; JavaScript cannot inspect the forbidden Set-Cookie header. The anonymous snapshot route never sets cookies. Browser Cache does not honor HTTP cache headers; own version/expiry/byte/count enforcement is mandatory. Limit snapshots to 512 KiB, 30 items and 2 MiB total, expiry seven days from explicit save. Browser storage may be denied/evicted. Offline copies cannot discover publication revocation while disconnected; explain it. Online denial removes saved content; changed sources require deliberate refresh. Keep public online navigation usable without worker support.

Recovery capabilities are high-entropy, stored hashed, not logged or included in URLs sent to the server as referrers. Explicit same-origin POST mutations, current editor checks, publication-bound purpose, canonical allowlisted scalar values, finite counts/bytes/expiry and consistent parent-form lock ordering. No covert autosave/exit monitoring. Queue admission and actual delivery preflight both check recovery authority; no generic notification bypass. Integrate maintenance, private subject export/erasure and portable recovery graphs.

New persisted recovery tables use reviewed native25 / portable20, explicit stopped native upgrade and offline archive conversion from authentic original D11 data. Ordinary restore accepts only the current grammar; no request-time compatibility layer. Retain all prior migration verification.
