# Publication-aware discovery

Open Language & discovery in the content editor to inspect an illustrative working-copy preview, choose a local social image and optional alt text, attach a central relevant local video, and declare a news publication. Title/description remain shared draft/revision/publication fields. Search and social platforms choose their own final appearance; this is not an exact external preview or a ranking promise.

All chosen assets use the existing local Media library. Public Open Graph image URL/type/alt and available dimensions require current public unrestricted image access. Blank alt uses the library description. Missing, private or member-restricted assets are omitted; publication does not grant access. The preview loads only same-origin admitted media. No vendor account or outside resource fetch is used.

A local MP4 plus poster, title and description renders visibly below content using the shared theme renderer. Enable video discovery only when the video is central and relevant to that page. Both assets must stay public/unrestricted for a video sitemap entry. Broader video composition, captions and optional video sitemap fields are not asserted here.

News requires Article output, a truthful publication name and a bundled registered ISO language code (two or three letters; Chinese zh-cn/zh-tw). Non-identifying/reserved/unknown codes are refused. The original first publication date governs the two-day news window; edits do not reset it. The news title is the actual published content title. Publisher names and article relevance remain owner-authored facts, not independently certified external acceptance.

Robots points to /sitemap-index.xml. General content pages retain their existing 1,000-record boundary. /discovery-sitemap/image, /discovery-sitemap/video and /discovery-sitemap/news use independent keyset pages of at most 100 eligible publication records. The index includes each actual page, even intentionally empty first pages, and refuses above 500,000 eligible records per type. Editorial image references are indexed atomically at publication and rebuilt from canonical documents on stopped upgrade/fresh recovery, avoiding document scans in sitemap requests. Up to 1,000 distinct local editorial images per content item; at most 32,000 resolved image references/four MiB XML per page, otherwise explicit refusal without truncated output. Noindex/draft/member resources and revoked assets stay out of public discovery. Each extension response uses a consistent database snapshot and no-store. Across separate requests/keyset recrawls, later publication and expiry changes may alter pages; this is not a frozen export.

Native schema 20 / portable graph v16 / theme package 2. Stop every process/worker, retain the actual schema-19 binary and original encrypted recovery point, then use upgrade preview/exact execution. Rollback means a fresh target restored with the matching old binary, never opening upgraded data with it. migrate-recovery-v15 creates a new validated v16 archive; ordinary restore refuses old envelopes. The derived image index is not a separately trusted portable table. Older supported explicit converters remain bounded maintenance tools, not runtime fallback. Historical content titles with control characters must be corrected before recovery or upgrade; malformed XML is refused rather than silently rewriting published text.

Scope: canonical local editorial document images only. Theme/dynamic/raw-HTML/foreign-URL image breadth remains tracked separately. Social image mapping from WordPress is not implicit; choose admitted identities. Full free/premium plugin UI/widget parity and licensed premium reference execution remain outside the selected comparison. Guidance version/check date, uncertainty and next review live in the feature manifest; sites continue offline with bundled rules.
