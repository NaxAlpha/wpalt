## Security and limits

No imported credentials, source PHP/serialized objects, inferred consent/grants/settlement or automatic remote media access. Mapped packages are checked as a complete native graph before writes. Fresh recovery clears integration grants/event history and initializes a new epoch; physical rollback still requires explicit authority and consumer reconciliation. Owner review and independent source retention are required for unsupported mappings, source queues, stock/access/consent and new publication. Source version strings are declared provenance; actual installed-plugin reports provide separate reference evidence.

Existing session/role/CSRF/origin, TOTP/passkey, private media, optimistic concurrency, finite quotas, commerce receipts, recovery integrity and request/cache boundaries remain cumulative controls. Debug/audit diagnostics identify grant UUIDs and safe metadata, not bearer tokens, source bodies, webhook keys or private exports. Extensions execute outside the CMS process under owner OS/network/resource policies.

**F023/F024 remain precisely tracked:** bounded real local AI and selected Elementor document projection have evidence; all-template/widget/style/dynamic-condition/runtime or pixel compatibility is not implemented. M8's selected mapping/loss-report contract must not be advertised as complete Elementor parity. M9 retains the distributed execution/upgrade baseline; unsupported migration data is not quietly moved there or discarded.
