Cache-enabled and uncached phases run serially; default background work remains included. `scripts/adversarial_benchmark.py` measures one versus 100 half-megabyte promotion candidates with correlated SQL counts, response bytes, resident snapshots and observed latencies.

The current macOS optimized implementation (`81db3d3` code) measured a 25,580,384-byte executable (24.4 MiB), roughly 19.2 MiB synthetic site data, 48.5 MiB loaded RSS with public caching and 57.6 MiB without. At concurrency ten, cached public p95 values were about 2.5–3.4 ms; uncached full sitemap p95 was 139.5 ms and article p95 57.9 ms. These are single-run localhost observations including client overhead and background contention, not universal budgets or field Core Web Vitals. Resident snapshots are not peak allocation. Optional codecs, PostgreSQL and original media add their own costs.

Query evidence: sitemap cursor uses `published_sitemap` plus indexed protected-resource exclusion; account content export uses the covering author/id index; subject history uses its compound index; owner requests select their bounded page through `privacy_owner_queue` before joining names. The 120-record high-level queue journey proves all later pages remain available. Promotion selection remained **eight correlated SQL queries** with both one and 100 large candidates. Timing assertions do not replace state correctness.

`scripts/matched_wordpress_benchmark.py` runs a separate, focused M7 PR job on the same Linux runner as its clean executable. It records official image identities, WordPress 7.1.2 and actual free ACF/Yoast/UpdraftPlus/WP Super Cache/WooCommerce versions, matching 1,000-article text and twenty-item template, article/search/sitemap paths, warm cache files, latency and application/database disk/cgroup memory. ## Operational/security limits

One owning process remains the supported mode. Distributed caches/jobs/replicas/coordination belong to M9. Independent copies protect host loss only when actually independently retained and recovery keys remain available. Logical backup encryption does not encrypt native PostgreSQL base directories; retain/protect native chains and media consistently. Purely local pattern scans are warnings, not current reputation/signature intelligence. Native-peer CIDR labels are owner-supplied presentation data, not a live global geolocation dataset. Cloud WAF/DDOS/CDN/vault/shared spam remain external.

FFmpeg is optional and owner-installed, with bounded application admission, size/duration/pixels/deadlines and fixed arguments. Its per-allocation limits do not replace OS process isolation/aggregate quotas. Declared optional scripts are privileged owner code, not a sandbox or generic external tag manager; withdrawal cannot erase independently written outside data. Anonymous forms, visitor cookies, provider records and independent backups require separately verified privacy review. Partial account removal preserves stable financial identifiers and records retained-data reasons; no legal or universal-erasure certification.

Clone activation is an operator decision after source/queue/provider/identity review, not proof of exactly-once external payment or mail execution. Keep staging copies held and credentials disabled. Recovered mail acceptance can remain uncertain; domain state controls retries, not the audit/job journals.
