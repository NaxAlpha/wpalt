# M4 initial form slice — evidence and remaining work

2026-10-02, development evidence. PR #8 remains a draft; this document is not milestone completion or premium-plugin parity.

The owner creates a form, configures text/number/checkbox fields, visibility and steps, saves/publishes, and views preserved responses. The browser cluster submits an unchecked business checkbox, then a conditional required company, verifies owner-only viewing and literal rendering of supplied markup, reaches the configured limit and confirms the visitor's work remains in the open page. No form-script exception or remote request occurred. `scripts/business_acceptance.cjs` runs inside the existing browser acceptance fixture.

The four readable `tests/business_rules.rs` clusters establish authoritative hidden/derived values, typed partial rules/final validation, invalid dependencies/repeater bounds, and transactional publication/deduplication/recovery. The storage journey uses independent pools, freezes reusable groups across schema changes, restores to a fresh engine, checks stale publication and payload reuse, races for the last response slot, verifies private access and verifies that disabling business removes its asset. Real PostgreSQL is mandatory when `WPALT_REQUIRE_POSTGRES=1`; locally only SQLite is available. Initial backend commit `7349159` passed all three jobs in run 37003012725, including actual PostgreSQL; that evidence predates the UI/capacity extensions and does not verify a newer head.

Local checks after the UI extension: SQLite form/storage/recovery and the 19 existing publishing acceptance clusters, formatting, warnings-denied Clippy, locked frontend regeneration, feature-guidance freshness and full native macOS Chrome browser acceptance with the existing independent UI contracts. The form designer's 320/1440 geometry measurements had no failures; the 320px visitor sample had no horizontal overflow, controls at least 44px high and 6px radii. One focused desktop designer axe scan had zero violations; this is not full accessibility certification. Existing 38 UI measurements/12 accessibility samples/three reviewed gallery comparisons remain separate regression evidence. Raw form geometry and journey output: `work/browser-evidence/business-forms.json`.

Inspected actual desktop/narrow form screenshots: cardless admin sections, shared native controls, readable error/status feedback and no horizontal document overflow. The desktop field controls share a compact three-column row; narrow screens stack. Public controls retain the site's chosen theme and a visible focus outline. The loading placeholder is removed when the interface becomes usable. No screenshot baselines were regenerated to approve this change.

Publication schemas are stored once per form version and referenced by entries rather than duplicated per response. Only reachable reusable groups enter a public publication. Entry insertion serializes against publication and quota using a database write lock before reads, with a unique `(form_id, request_key)` constraint and immutable publication foreign key. This conservative lock still needs representative throughput/query-plan/resource measurements before M4 delivery. Listings project bounded summaries; detail reads join a publication once. Recent-40 views are an initial limit, not complete pagination/export/search.

Current limits and gaps are in [business operations](../business.md) and the [M4 contract](../m4-contract.md). Complete typed widgets/designer, files, signatures, surveys/pricing, durable partial/offline recovery, embedded editor/theme integration, moderated actions, audience, communications, engagement, operational/backup extensions and integrated security/performance/UX verification remain required.
