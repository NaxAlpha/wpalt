# D11 — Private attachments and attested response documents

Date: 2026-10-12. Starts from D10 PR26, merged main `ca77d2c422d5135bf889c7fd13329f577fbc83ae`, identical to the seven-gate tested tree. Actual-main/public release is independently verified ([receipt](evidence/d10-main-release.json)). Catalog F041/F043. No full plugin parity or certified identity claim.

## End-user outcome

An operator optionally enables an owner-hosted malware engine for private form attachments. Configured scanning refuses detected files, unavailable/slow/malformed engines and exhausted admission before issuing a capability; existing private downloads also obey current scanning policy. Disabled scanning is clearly labeled unscanned. An owner reviews the original frozen response/acknowledgment and downloads a printable, cryptographically attested document bundle. An independent verifier checks exact document bytes with an explicitly trusted public key and rejects changes or the wrong key. Optional local Chromium produces a PDF under fixed bounded worker rules; the ordinary application does not require Chromium, Node or a cloud service.

## Authority and failure boundaries

Use a configured absolute Unix ClamAV socket, explicit NUL framing and bounded INSTREAM chunks/replies, a complete operation deadline and finite admission. Scan original input before image processing and normalized bytes before storage. Re-scan old/private attachment downloads when enabled, after integrity checks and before disclosure. No filename-based daemon commands, remote unauthenticated scanner socket, shell execution or retained daemon answers containing user data. Owner-hosted signature intelligence and OS daemon isolation are operational requirements, not a universal malware safety guarantee. Observe actual engine/version evidence; a controlled signature fixture does not prove fresh official intelligence.

An Ed25519 server attestation binds a versioned/domain-separated serialized manifest containing canonical accepted values to the exact generated artifact digest, original response ID/time, frozen publication/statement, canonical accepted values and private attachment digests. Use locked ring 0.17.14 and RFC 8032. Independently trusted key identity is necessary: shipping a key beside a signature alone cannot prove identity. Typed names remain declarations; server signing does not prove respondent private-key possession, identity, legal certification, PAdES compliance or a qualified electronic signature. Those identity/provider capabilities remain explicit external follow-ups and must never be silently marked complete.

All document routes require current editor permission and same-origin/CSRF authority for generation. Bound accepted data, document/artifact bytes, deadline and concurrency; escape owner/visitor text. Generated PDF workers get only locally generated content, fixed arguments and no executable user content. Optional worker isolation/resource limits must be documented; do not claim an application timeout alone is OS memory/network containment. Re-check authority before private disclosure. Do not log answers, names, document bytes or private keys.

## Storage and configuration decision

Prefer on-demand artifact generation from existing immutable publications/accepted responses; no new stored response grammar/table or automatic old signature reinterpretation. Preserve current native 24 / portable 19 if implementation genuinely introduces no persisted state. Generated downloads are retained by their recipient; backups preserve source records, not a previously downloaded PDF's exact renderer metadata. Signing keys are explicit owner-controlled private files with separate backup/rotation; public fingerprints join local-process startup identity so changing key bytes cannot silently change an active node. Verification of saved artifacts remains possible with the original trusted public key after rotation. CLI/configuration must describe disabled/default and missing-key/worker failure clearly.

## Meaningful verification

Readable clusters cover actual accepted upload/acknowledgment/document/download and tampering/wrong-key/private/current-role failures on SQLite and real PostgreSQL; scanner unavailable/slow/truncated/oversized/FOUND refusal with no file/quota/capability side effects; upload contention/single-use capabilities and fresh recovery with original source data; bounded escaped long/Unicode statements/answers and signatures. Execute an actual isolated ClamAV engine with a controlled signature and record its scope, plus independently verify actual signatures using another implementation. Inspect representative populated/failure screenshots and measured layouts at 320/768/1440 with keyboard/scoped accessibility. Exercise two local app processes/worker with exact binary identity; record query/resource/worker measurements without claiming physical hosts, peak memory or a throughput SLA. Preserve all cumulative clean-build/release gates and auto-merge only the ready exact tested source.
