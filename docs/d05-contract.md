## End-user outcome

An owner reviews a source Elementor design, sees concrete mapped and unmapped elements/settings, and creates a private editable native component/theme draft. Responsive layout, typography, local images, links and selected interactive structures use shared native composition and permissions. An explicit target prevents one imported page from silently replacing unrelated pages. Preview and deliberate publication use the existing Studio workflow. Source, base version, mappings and review decisions determine an exact fingerprint; stale review cannot overwrite newer work.

## Functional and optimization sequence

1. Inventory the pinned current free source's legacy and atomic element/control/style families. Distinguish plugin release, export schema and actual runtime-observed data. Reuse the existing native component/style/media/binding system rather than duplicating a rendering or access engine. Define input, aggregate node, byte, depth and output limits before writes. A large valid source may exceed native composition limits; report/refuse that boundary rather than truncating it.
2. Implement an offline projection/report into current native theme/component grammar. Preserve ordered content and source identities; account for unsupported settings, global/dynamic references, display conditions and extra atomic fields. Accept bounded declared styles and safe literals only. Unknown units/controls are explicit losses. Arbitrary CSS/scripts/PHP/widgets do not acquire native execution rights. Media/font mappings resolve admitted local identities; no remote resource fetch, foreign file traversal or license inference.
3. Deliver a connected owner review/import workflow. Default to a private draft/reusable component; selecting home/header/footer or a specific content target is explicit. Preserve the original base and unrelated page/template behavior. Preview/publication, exact versions, current credentials and dependency validation remain authoritative. Unsupported source condition/access cannot create a public grant. Content-only migration remains a separately labeled valid workflow.
4. Expand supported current free widget/atomic families and reusable/global/style/dynamic mappings with an inventory that records each supported subset and retained breadth. Include meaningful native local equivalents where appropriate and state differences. Genuine external-service embeds stay separate dependencies. Pro behavior stays documentation-only without licensed owner-provisioned fixtures; inaccessible source is not falsely marked executed.
5. Verify connected native components and integrated owner/visitor/migration/recovery journeys on real SQLite/PostgreSQL. Cover malformed/oversized/deep/duplicate data, executable or unsafe links/styles, ambiguous dependencies, exact review/stale edits, private/live isolation and unrelated-page preservation. Extend shared geometry/accessibility tests for new interactions. Use actual current free-plugin container exports/rendering for comparison, with versions/hashes and concrete differences; source inspection alone is not runtime parity.
6. Optimize bounded parsing, request/query work, native stylesheet/component reuse and memory/disk. Record declared resource and query observations without ranking/performance/aesthetic promises. Keep all cumulative CI/security/recovery/maintenance/browser gates and independently verified exact-head clean archives. Create/auto-merge a significant delivery PR only when ready, then verify actual-main release independently.
