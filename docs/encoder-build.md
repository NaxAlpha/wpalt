# Build-time encoder preparation

Run `python3 scripts/prepare_encoder.py` before any Cargo command in a fresh checkout. All Rust CI jobs do this, including dependency audit and the Rust 1.88 compiler floor. Generated `vendor/rav1e` is ignored by Git; the existing Cargo path patch and lockfile stay unchanged. No application, image-processing algorithm or deployment format changes.

The script downloads rav1e 0.8.1 from `https://static.crates.io/crates/rav1e/rav1e-0.8.1.crate`, with SHA-256 `43b6dd56e85d9483277cde964fd1bdb0428de4fec5ebba7540995639a21cb32b` and original VCS `38806721f718e7ae6919e72385bc305bf824ef81`. It applies the upstream [pastey migration](https://github.com/xiph/rav1e/commit/c247d53ae43dd1312dbd90117c45e4c0ee6b06ce) and two explicit lifetime annotations for newer compilers. LICENSE/PATENTS remain intact; notices stay in the release.

The archive is limited to 16 MiB and expanded regular-file content to 32 MiB/2,000 files. Checksums are checked before parsing. Unsafe paths, links, duplicate files and changed patch targets fail. Files are written manually into a staging directory, verified, then published. Subsequent runs verify every generated byte against the checksummed archive and exact transformations; they reject tampering instead of silently reusing or overwriting it. On a reported source mismatch, remove only generated `vendor/rav1e` and rerun preparation. On a checksum failure, replace the archive with the exact pinned original; never change the pin merely to make the check pass.

The original archive is retained in ignored `work/build-dependencies/rav1e-0.8.1.crate`. Repeated preparation needs no network when this archive exists. For an offline build, supply a previously downloaded original using `python3 scripts/prepare_encoder.py --archive /path/to/rav1e-0.8.1.crate`; the same pinned checksum and validation apply. CI clean builds download afresh and do not restore this archive, source or Cargo caches.

Python 3 is a build tool only. Deployed wpalt neither downloads this source nor needs Python, Cargo or an extra runtime service. Removing the files from the new Git tree reduces checkout size, not binary size; existing Git history still contains the earlier copy. No history rewrite is performed.

Removal condition: replace preparation/path patch with a reviewed registry release containing the maintained macro dependency, passing Rust 1.88, selected-graph audit, real AVIF/browser decode and footprint checks. Review monthly and on upstream changes through M7-NATIVE-AVIF.
