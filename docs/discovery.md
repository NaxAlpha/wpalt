# Multilingual publishing and discovery

M3 is an owner-hosted discovery system. It adds no service account, subscription, production Node process or outbound crawler.

Open **Discovery** in the admin panel. Add languages using registered language/region identifiers such as `fr`, `ar` or `en-gb`, human-readable names, writing direction and translated search text. The accepted syntax is a bounded subset (two/three letters with an optional short region); syntax validation does not certify registration. Open a language disclosure to edit its settings. Configure translated navigation in the nested navigation disclosure as an array of `{ "label": "…", "url": "/fr/…" }`. Empty language navigation uses shared Site settings navigation. Admin chrome and built-in public comment/utility labels remain English; a full translated message catalog is not yet delivered. Public content/navigation are authored translations, not automatic translation.

Each content editor has **Language & discovery**: select its language, assign the same translation group to related variants, and independently save/preview/publish each variant. Groups have one variant per language and one content type. Slugs are globally unique. The default language uses `/story`; other languages use `/fr/histoire`. Only published, indexable variants appear in reciprocal hreflang and the language selector. Missing variants are omitted; shared typed relationships remain explicitly cross-language. Collections, home/search and public content API use the selected language. `/api/content?lang=fr&q=…` supports language-scoped indexed search. RSS currently contains the default language.

Search title/description overrides, indexing policy and Article/WebPage type use the same working/publication snapshots and revision history as content. Saving a working copy does not change live metadata. Native form publishing works without JavaScript. A noindex page is still public: this policy is not access control. It is omitted from sitemaps and internal discovery lists/search. Private administration/preview responses carry noindex headers. Search pages are noindex. Canonical/social/structured output has one renderer; themes do not inject competing heads. No external canonical override is accepted.

The structured output is a minimal truthful WebPage/Article document and optional LocalBusiness node. Business identity/address is visibly rendered alongside that node; no ratings, opening hours, images, author claims or dates are invented. This is not every schema type, a custom schema graph editor, multiple locations, or a guarantee of Google rich-result eligibility. In particular Article's recommended image/author/date enrichment is not claimed delivered. The sitemap does not manufacture `lastmod` from draft timestamps.

`/robots.txt` points to `/sitemap-index.xml`; its sitemap pages contain published indexable content URLs. Each page scans at most 1,001 publication records, emits at most 1,000 URLs and exposes the next cursor. The index uses two bounded database scans, returns at most 500 pages and explicitly rejects sites above its 500,000-record budget. Noindex filtering may leave sparse pages. These are keyset views of current publication, not a frozen concurrent snapshot; a recrawl observes later publications. Neither robots rules nor noindex replace authentication.

Exact redirects accept local paths and HTTP 301/302. Up to 1,000 rules, at most 15 hops, no cycles, private routes, external targets, or published/scheduled/language-route conflicts. Existing rules can be removed and recreated; no regex engine, arbitrary catch-all, 404 analytics or automatic slug history is claimed. Unknown local targets can be authored deliberately and inspected with the link checker.

**Check published local links** reads up to 20 published Markdown sources and 200 destinations per batch, resolves local links/public media and redirect chains with batched queries, and reports unresolved paths. Relative links resolve against the actual published document path. External links, fragments and protocol-relative external links are skipped; no HTTP fetch means no SSRF/crawler dependency. Raw HTML links and theme-generated links, global orphan graphs and external reachability are outside this checker.

Language/SEO/redirect changes use existing mutation serialization, optimistic versions and database constraints. Single-server SQLite/PostgreSQL are the supported current runtime; M9 owns distributed write coordination. Public responses are uncached, so publication and policy changes appear on the next request without cache invalidation lag.

## Upgrade and recovery

Stop writers and preserve a backup/database copy before changing binaries. Schema 2 upgrades once to schema 3; schema 1 upgrades through schema 2. Working/publication metadata and old revision envelopes are populated with English/default SEO, preserving existing URLs and content. Subsequent starts use only the current schema. Downgrade requires restoration of the saved old database using the matching old binary.

Current exports are `wpalt-backup-v3`. Restore only into a fresh target; its untouched default discovery row is allowed, but configured or populated targets are rejected. Semantic validation checks languages, SEO, translation groups and local noncyclic redirect rules before writes. For a v2 archive, restore with the M2 binary into a fresh database, then stop it and open that database with M3. There is no legacy archive parser in M3 normal operation.

JSON content API callers must send current `locale`, `translation_group` and `seo` values when editing; omitted metadata gets new-content defaults, not preservation of old values. Update callers together before adoption. Default language can change only before content exists; established-site default changes require a future explicit URL migration. In-use languages cannot be removed.

Guidance review and future maintenance use [the evidence manifest](evidence/feature-guidance.json) and `python3 scripts/check_protocols.py`; affected releases and upstream changes trigger semantic review. Sites remain usable offline with bundled rules.
