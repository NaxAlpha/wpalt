# Redirects and published links

Native schema 22 / portable recovery v18. This guide describes the supported local controls; delivery status, reproducible evidence and remaining limits are tracked in [D08 verification](evidence/d08-verification.md).

Open **Discovery → Redirect & missing-link workspace** (`/admin/discovery/routes`). Native owner forms work without JavaScript. Exact rules win over owned publication aliases, followed by enabled capture rules ordered by priority and identifier. Existing real routes retain authority. All supported destinations are local safe ASCII paths; query strings are discarded rather than forwarded. A redirect to an unserved destination can still result in a missing page.

For a capture rule, choose a stable identifier and understandable label, an anchored path expression such as `^/old/([a-z0-9-]+)$`, and a local replacement such as `/articles/$1`. Preview a path before saving. Preview temporarily includes the proposed rule, displays selected overlaps and traversed hops, and performs no save. It rejects unsupported syntax, unsafe expanded destinations, loops and excessive chains. Samples cannot prove that every possible pattern combination is safe; runtime resolution retains those checks. Lower numeric priority runs first, then identifier order. Rust syntax supports numbered captures but excludes PHP PCRE lookaround and backreferences.

**Automatic publication redirects** is opt-in. Saving a working draft does not create a redirect. Publishing a new address moves owned aliases to that actual publication atomically. Rename-back removes the destination's own alias. Manual rules and another publication's aliases cause a conflict instead of being overwritten. Unpublishing removes owned aliases. Disabling automatic creation stops new aliases and preserves retained ones for explicit review/removal. Current protected or revoked destinations do not become redirect existence signals.

**Retain missing public paths** is off initially. When enabled, admitted missing GET responses aggregate safe path, count, first/last time and version. HEAD responses, queries, client addresses, headers and bodies are not retained. Private and reserved routes are excluded. Slugs themselves may include personal information; choose an appropriate retention period. The initial limit is 500 paths and 30 days; configurable ranges are 1–2,000 paths and 1–90 days. New paths are skipped at capacity while existing counts continue. Incoming reports and the `missing-path-retention` job remove expired entries. Run the configured jobs for retention when no traffic arrives. Disabling deletes retained entries; purge and per-path deletion are explicit owner actions. Counts are requests, not unique people.

The JSON owner API at `/api/discovery/redirect-policy` reads the versioned policy. POST requires an authenticated administrator and a JSON object containing `csrf`, `version` and `settings`. Settings include `automatic_slug_redirects`, `report_404`, `retention_days`, `max_paths` and `rules`. The API updates settings without accepting caller-forged alias ownership. A stale version returns 409. Input limits and destination rules are identical to native forms.

Stored semantics require native schema 22 and portable recovery v18. Use stopped maintenance and the explicit v17 converter for supported D07 data. Never relabel an archive or downgrade live tables manually. Migration, original-runtime rollback and release evidence are tracked in [D08 verification](evidence/d08-verification.md).

Open **Rendered link graph** from the workspace. Analysis is an explicit owner POST, rather than work performed while merely opening the screen. It renders canonical anonymous publications and enumerated language landing pages using the same server rendering as readers, including navigation, raw body HTML and native bindings/conditions. The graph includes anchor and image edges, source byte counts and HTML digests. Broken/refused edges appear first; other edges and source lists are collapsed. Download JSON for the complete result rather than treating the bounded on-screen sample as the whole graph.

Local source, publication-alias, redirect and original-media targets are distinguished from broken targets. Original media requires current public access and an existing valid file. Media derivatives remain explicitly unscanned. Fragment checks cover actual IDs/named anchors, percent-decoded forms and `#top`; browser text directives remain unscanned. Query states, reserved/encoded paths, external origins, non-HTTP schemes and private publications are explicit exclusions, with no network fetch. “No inbound anchors” describes this declared graph and does not establish whole-site orphan status or search indexing.

The complete graph admits at most 1,000 public publications, enumerated language landings, 20,000 edges, 2 MiB per source, 64 MiB aggregate HTML, 50,000 tree nodes per source, depth 64 and a 20-second total work budget. A streaming preflight caps 50,000 lexical tokens and 128 raw open tags before DOM allocation; it can conservatively refuse malformed/self-closing non-void markup. Overflow or a publication-generation change refuses completion and emits no partial orphan conclusion. Existing published-link checks remain available. External link fetching, client-generated links, infinite search/filter states and complete paid-plugin parity are outside the declared D08 graph.
