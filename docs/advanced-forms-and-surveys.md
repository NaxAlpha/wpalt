# Advanced forms and survey reporting

D10 development; delivery verification pending. Native24/portable19. [Contract](d10-contract.md), [verification](evidence/d10-verification.md). The D09 development release remains the independently delivered version until D10 passes its own gates.

Open Business → Forms, create or edit a form, then use each field's Visibility and calculation disclosure. Conditions can combine all/any/not rules, presence, scalar equality/membership and numeric comparisons. References must use earlier fields. Number fields can compose typed calculations from constants, earlier numbers/choice scores, arithmetic, min/max/average, transforms and conditional branches. A conditional branch evaluates only its selected result, allowing an intentional alternative to missing/skipped inputs. Missing is never zero; division by zero and non-finite results refuse. Rounding uses zero to eight decimals and ties away from zero, including-2.5→-3. Calculations use binary64, not exact commerce currency or order pricing.

Try the working form before publishing. The browser offers a local preview; Check working form on server validates the current unsaved definition against current shared groups. It creates no response or notification/registration/consent/commerce action. Changing fields or inputs invalidates that confirmation. Server values are authoritative. Saving/publishing remains versioned; changing calculations does not reinterpret an earlier published definition.

The server discards hidden/derived visitor input, recomputes results, validates active typed fields and only then records a response and queues frozen actions. Native responses are available at `/forms/FORM_ID/native` for scalar questionnaires, choices and calculations. Review recalculates visibility/results through a server round trip, preserving work/errors. Accepted exact retries remain accepted after republishing. Richer structured/upload/signature widgets or enabled proof-of-work explicitly require the browser workflow; native POST never bypasses enabled abuse checks. Native pages containing user inputs are no-store/noindex.

Survey report links connect editing and individual responses. Choose a frozen published version and optional UTC interval (inclusive from/exclusive until); the report distinguishes eligible answered, eligible without an answer and conditionally skipped. Original question/option labels and scores stay bound to that version. Multiple-choice option totals can exceed the number of answered responses. Free text, attachment/signature contents and individual IDs are omitted; small aggregates are not a promise of anonymization. Numeric summaries describe recorded binary64 values, not representative populations or causal conclusions. CSV downloads are a new consistent snapshot for the selected version/period and may include responses committed after the on-screen report. Formula-looking owner labels/option text are escaped for spreadsheet import.

A report streams at most10,000 responses/32MiB total stored values/128KiB per response within ten seconds; limits are engineering admission caps, not latency or peak-memory guarantees. Over-budget work refuses without sampling or a partial summary; narrow the time cohort. The frozen definition and responses share one consistent read transaction (PostgreSQL REPEATABLE READ, SQLite snapshot). Version/time/id indexing isolates the selected cohort. Private HTML/JSON/CSV require current editor permission again before disclosure.

Administrative JSON uses existing same-origin sessions. `POST /api/admin/forms/FORM_ID/preview` accepts `{csrf,definition,values}` and returns canonical values/source digest without collection. `GET /api/admin/forms/FORM_ID/report?version=VERSION&from=YYYY-MM-DDTHH:MM&until=YYYY-MM-DDTHH:MM` returns the equivalent aggregate; empty dates select the entire version. `GET /admin/forms/FORM_ID/report.csv` accepts the same selection. Existing public JSON submission, drafts and quotas remain governed by the business guide.

Stopped native upgrade to24 and explicit portablev18→v19 conversion preserve original recovery points. Ordinary restore accepts onlyv19. Preserve original executable/configuration/key and prove fresh old-runtime rollback before switching. Numeric equality corrects the old Rust JSON representation mismatch (2 and2.0 compare numerically); unchanged historical canonical responses must validate before conversion. Any ambiguity requiring guessed missing answers fails preflight, rather than rewriting history. See [maintenance guidance](distributed-operations.md#d10-form-grammar-boundary).
