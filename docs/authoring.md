# Integrated authoring

Open Content → Create content. Write directly in the canvas. Type `/` in an empty paragraph, then choose a block; Arrow Down enters the insertion controls. Blocks also opens the chooser. Select text for contextual formatting and links, or open Format to prepare the next text; Ctrl/⌘ B/I and undo/redo work without leaving the canvas. Ctrl Home/End (⌘ ↑/↓ on Mac) navigates the document through editor transactions; Shift extends the selection. Lists support indentation. Tables support row/column insertion and deletion with Tab navigation; merged cells are intentionally unsupported. Organize reveals current-block movement and duplication through labeled controls; Ctrl/⌘ Alt ↑/↓ and the drag handle move top-level blocks.

The integrated image chooser lists uploaded images in bounded pages and fills `/media/ID` URLs and descriptions; descriptions remain editable. Media library opens separately so upload/visibility management remains available. Private media is never made public by embedding it. Paste accepts supported formatting and removes active HTML and remote pasted images. This is a publishing editor, not an arbitrary-HTML editor.

Language/discovery and typed fields are disclosures beneath writing. Preview, save, publish and scheduling use the same working/live snapshot contract as earlier milestones. Autosave updates existing drafts; a new item needs its first Save draft. A failed save keeps the canvas. Browser recovery offers an explicit restore/discard choice after reload; it is tied to this account and URL. Review a recovered copy before saving, especially when its original version differs from the server's current version. Another writer's save triggers a conflict rather than an overwrite.

Without the enhancement bundle, a native Markdown import form remains. Existing documents require explicitly selecting Replace content using Markdown; metadata-only saves preserve the canonical tree. Input entered before enhancement finishes is preserved and enhancement is skipped for that page. Markdown imports are not a lossless way to edit rich tables/callouts; prefer the direct editor and full JSON backups for those documents.

## API and recovery

Structured saves include `body:""` and send `document` as a JSON string containing `{version:1,root:...}` alongside existing metadata/version/action. The server derives the body projection; supplied body text cannot override the canonical tree. Leaving `document` empty requests an explicit Markdown `body` plus legacy `blocks` import. Those blocks are import data rather than separate rendered content. Current post/revision exports include the structured document; content export uses wpalt-content-v2. Validation limits: 2 MiB document JSON, 512 KiB text, 10,000 nodes, depth 16, basic tables up to 100 rows × 20 columns; existing request/config limits also apply.

Stop the server and capture an independent backup with the M3 executable before upgrading meaningful data. Schema 4 upgrades working/live documents and retained revisions atomically. Migration failures preserve the original transaction; test on a restored copy first. M3.5 snapshots use `wpalt-backup-v4`; the M4 development branch uses v5 as documented in operations. Restore older snapshots using their corresponding binary into a fresh target, then run the new binary to migrate the database. Downgrade by restoring the independent old backup to a fresh target. Do not open schema 4 with the old executable.

Maintain the authoring guidance record when the editor engine, browser input behavior, document grammar, accessibility guidance or relevant vulnerability changes. Rebuild assets from the locked frontend graph, run document/database and authoring/browser clusters, measure representative long documents, and review real screenshots before changing the UI contract.
